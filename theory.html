What is arbitrage?

Arbitrage means making a risk-free profit from price differences. In currency markets, triangular arbitrage is a loop of trades such as USD → EUR → GBP → USD that ends with more money than you started with, because the quoted rates are slightly inconsistent.

Step 1: model the market as a graph

Every currency is a vertex. Every possible trade is a directed edge labelled with the exchange rate. A loop of trades is a cycle in this graph.

A quoted pair has two prices. With a pair Base/Quote quoted at bid and ask:

TradeMeaningRate on the edge
Base → Quotesell the base currencybid
Quote → Basebuy the base currency1 / ask

Because bid ≤ ask, trading back and forth always loses a little (the spread). Arbitrage appears only when the rates around a loop do not line up by more than the spread.

Step 2: turn a product into a sum

Going around a cycle multiplies the rates. Money grows if the product is above 1:

r1 × r2 × … × rk > 1

Shortest-path algorithms add weights, they do not multiply. Taking logarithms fixes this, since log(a × b) = log a + log b. Using a minus sign flips the inequality:

w = −log(r)
r1 × … × rk > 1  ⇔  w1 + … + wk < 0

So arbitrage exists exactly when the graph has a negative-weight cycle.

Worked example. Rates 0.90, 0.86 and 1.30 give a product of 1.0062. The weights are 0.10536, 0.15082 and −0.26236, which sum to −0.00618. Since e0.00618 ≈ 1.0062, the profit is 0.62% per loop.

Step 3: Bellman-Ford

Bellman-Ford finds shortest paths even with negative edges, and it can detect negative cycles. It keeps a distance value dist[v] for each vertex.

  1. Initialise. Set every dist[v] = 0. Starting everything at 0 (instead of one source at 0 and the rest at infinity) lets the algorithm find a negative cycle anywhere in the graph, even if it is not reachable from one chosen currency.
  2. Relax V−1 times. In each pass, look at every edge u → v with weight w. If dist[u] + w < dist[v], update dist[v] and remember that u improved it (parent). This is called relaxation.
  3. Detection pass. Without a negative cycle, the distances are final after V−1 passes, because a shortest path has at most V−1 edges. So if any edge can still be relaxed on the V-th pass, a negative cycle exists.
  4. Extract the cycle. The vertex that was just relaxed may only lead into the cycle. Follow the parent links V times to be sure you are inside it, then keep following them until you return to the same vertex. Reverse the list to get the trade order.
  5. Compute the profit. Multiply the rates along the cycle and subtract 1.

Implementation details that matter

  • Store the edge, not just the parent vertex. Bid and ask edges can run between the same two currencies, so the parent must record which edge improved the node. Otherwise the profit may be computed from the wrong edge.
  • Use a small epsilon. Floating-point rounding can create fake negative cycles, so an update only counts if it improves the distance by more than 1e-12.
  • Validate input. Rates must be positive (log is undefined otherwise), currency names must exist, and bid must not exceed ask.

Limitations

  • The model ignores fees, trade size limits and the time it takes to execute trades. Real arbitrage disappears in milliseconds.
  • Only one cycle is reported, though several may exist.
